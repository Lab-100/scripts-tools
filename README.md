# scripts-tools

**INVR-Tools** — реестр версий инструментов оркестрации. Единый канон: здесь лежат
все версии всех инструментов, а потребители получают их через локер `resolve-tools`
и вызывают плоские шимы.

Дистрибутор, который ставит этот реестр на машину: [`devstation-deploy`](../devstation-deploy).

## Структура

```
registry/
  _registry.json          манифест реестра (список инструментов и latest)
  <tool>/
    latest.txt            указатель на актуальную версию
    <version>/
      tool.json           метаданные инструмента
      <entry>             исполняемый файл (или несколько)
<tool>.ps1, <tool>.cmd    плоские шимы в корне (генерируются локером)
project.json              манифест проекта: владелец, режим, требуемые диапазоны
```

Версии неизменяемы. Правка инструмента — это **новая версия** в новом каталоге;
старые каталоги не трогаются. Актуальная версия переключается правкой `latest.txt`.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `resolve-tools` | локер: разворачивает версии в проект, линкует, генерирует шимы |
| `backup-util` | каталог отката: бэкап изменений, журнал, откат по ChangeId |
| `mcp-watchdog` | демон-страж MCP-серверов и локальных сервисов |
| `infra-graph` | граф инфраструктуры: сервисы, порты, потоки, размеры |
| `opencode-status` / `opencode-monitor` | статус и мониторинг opencode |
| `opencode-plugins` | установка плагинов opencode |
| `browsertool` | headless-браузер (драйвер + протокол на 127.0.0.1:8123) |
| `doc-extract` | извлечение текста/таблиц из документов пулом OCR-провайдеров с судьёй |
| `ai-provider-check` | проверка доступности и ключей ИИ-провайдеров |
| `gordon` / `gordon-chat` | маршрутизация к облачным и локальным ИИ-провайдерам |
| `firecrawl-key` | получение и обновление ключа Firecrawl |
| `llm-mcp` | MCP-мост к локальным моделям Ollama |
| `vmdisk` | виртуальные диски Hyper-V с обязательной меткой и учётом |

## Использование

Локер читает `project.json` проекта, разрешает диапазоны версий, скачивает нужное
из этого реестра и создаёт junction-линки `<проект>\tools\<tool>` плюс шимы.

```powershell
# развернуть инструменты в проект и сгенерировать шимы
.\resolve-tools.ps1 link -Project C:\path\to\project -GenerateShims

# что установлено / что доступно
.\resolve-tools.ps1 status -Project C:\path\to\project
```

Корень реестра переопределяется переменной `INVR_REGISTRY`, иначе берётся
`$PSScriptRoot\registry`. Шимы генерируются на целевой машине, поэтому в них
прописан фактический путь к реестру — это нормально.

## Приватные настройки и секреты

**В коде и в этом репозитории нет ни ключей, ни паролей, ни личных путей.** Принципы:

- Ключи API читаются **только из переменных окружения** (`Get-EnvStrict`).
  В коде нет значений, в репозиторий не попадает ничего секретного.
- Пути машинных каталогов задаются переменными окружения или параметрами
  (`INVR_REGISTRY`, `INVR_ROLLBACK_ROOT`, `HERMES_EXE`, `BROWSERTOOL_PORT` и др.),
  в коде — переносимые дефолты.
- Персональные настройки хранятся в файлах `*.local.json` и `config.local.json`.
  Они в `.gitignore` и в публичный репозиторий не попадают.
- Региональные и машинные особенности в публичном коде описаны нейтрально
  («недоступен в некоторых регионах»), без привязки к конкретной стране.

Поэтому репозиторий можно читать, форкать и ставить на любую машину: приватное
остаётся в локальной копии и в окружении, а в общий код попадает только
переносимая логика.

## Требования

- Windows 10/11, PowerShell 7 (`pwsh`)
- Node.js 18+ — только для `browsertool`
- Ollama — для `llm-mcp` и локальных субагентов
