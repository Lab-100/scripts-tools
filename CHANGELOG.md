# Журнал изменений

Версии проекта — по схеме «основная.младшая» (без третьего компонента),
даты в формате ISO (ГГГГ-ММ-ДД).

Версии инструментов в `registry/<tool>/<version>/` ведутся по semver (X.Y.Z) —
это другая шкала, они неизменяемы и в этот журнал проекта не входят.

## 0.9 — 2026-10-16

### Добавлено

- `mcp-watchdog 0.6.0` — троттлинг ресурсов локальных моделей: демон следит,
  чтобы в системе оставалось **не меньше 10% свободной памяти** и **не больше
  85% загрузки процессора** (то есть свободно не меньше 15% процессорного
  времени). Два эшелона: мягкий — процесс runner'а Ollama (`llama-server`)
  каждый цикл опускается до `BelowNormal`; жёсткий — при нарушении порогов из
  памяти выгружаются только реально загруженные модели (`GET /api/ps`),
  потому что `POST /api/generate` с `keep_alive=0` для незагруженной модели
  сначала её аллоцирует, и только потом выгружает.
- Чистая логика решения вынесена в
  `registry/mcp-watchdog/0.6.0/throttle-lib.ps1` и покрыта тестами
  `tests/throttle.Tests.ps1`: правило выгрузки (пороги, гистерезис,
  антидребезг, режим `report`) проверяется без Ollama и без изменения процессов.
- Снимок троттлинга публикуется в `state/current.json` (раздел
  `resourceThrottle`) и в `state/throttle.json` (последнее действие и счётчик
  выгрузок).
- Новые параметры демона: `-ThrottleMinFreeMemPct`, `-ThrottleMaxCpuPct`,
  `-ThrottleResumeMemPct`, `-ThrottleResumeCpuPct`, `-ThrottleMinGapSec`,
  `-ThrottleMode enforce|report`, `-NoRunnerPriority`, `-OllamaHost`.
- `mcp-watchdog 0.6.1` — нарушение порогов видно в журнале и в `current.json`
  (`resourceThrottle.breached`), даже когда ни одна модель не загружена: раньше
  такой случай молчал, и источник нехватки памяти или процессорного времени
  приходилось искать вслепую. Интервал записи — `-ThrottleBreachLogSec`
  (по умолчанию 600 с), чтобы журнал не забивался одинаковыми строками.
  Решение о выгрузке и сами пороги 0.6.0 не изменились.
- `mcp-watchdog 0.6.2` — один демон на машину, гарантированно. Экземпляр берёт
  эксклюзивную файловую блокировку `state\watchdog.lock`
  (`FileShare::None`): атомарно и без зависимости от WMI. Прежняя защита по
  pid-файлу опиралась на один запрос `Get-CimInstance`, который на этой машине
  периодически не отвечает, из-за чего guardian успевал поднять второй демон —
  два демона писали один `current.json`, каждый поднимал свой `local-llm`
  (четыре процесса вместо двух), а зомби-экземпляры ели процессорное время.
  Разовый прогон `-Once` блокировку не берёт.
- `mcp-watchdog 0.6.3` — исправлен возврат значений функций, которые пишут в
  журнал. `Write-Log` печатал строку в поток вывода через `Write-Output`, поэтому
  функция с `return $false` возвращала массив (строка лога, `$false`) вместо
  логического значения. Из-за этого `if (Start-OllamaServer)` и подобные проверки
  авто-подъёма всегда считались успешными, а блокировка из 0.6.2 теряла результат
  и демон-дубль проходил. Журнал теперь печатается через `Write-Host`: вывод в
  консоли тот же, возвращаемые значения чистые. Демон запускается в фоне, так что
  поток вывода ему не нужен.
- `mcp-watchdog 0.6.4` — исправлена выгрузка моделей, которая не работала вовсе.
  `Get-InvrOllamaLoadedModels` возвращал список через оператор запятая
  (`return ,$models`), то есть массив внутри массива; вызывающая сторона оборачивала
  результат в `@(...)`, и в цикл выгрузки попадал весь массив вместо имени модели —
  `Unload-InvrOllamaModel -Model` падал с ошибкой приведения к строке. Теперь функция
  отдаёт плоский массив строк, а в цикле имя приводится к строке. Жёсткий эшелон
  троттлинга (выгрузка при нарушении порога) фактически не работал с 0.6.0; мягкий
  эшелон (понижение приоритета `llama-server`) работал.
- Переменные окружения экономного инференса: `INVR_LLM_NUM_CTX`,
  `INVR_LLM_KEEP_ALIVE`, `INVR_LLM_NUM_THREAD`, `INVR_LLM_NUM_PREDICT`,
  `INVR_LLM_NUM_BATCH`, `INVR_LLM_MODEL_ALLOW`.

### Изменено

- `llm-mcp 0.3.0` — экономные лимиты инференса: `num_ctx` 16384 → **4096**
  (KV-кэш по окну контекста — главный расход памяти помимо весов),
  `keep_alive` 30m → **3m**, добавлены `num_thread` (2), `num_batch` (256) и
  потолок ответа 768 токенов. Прежние значения возвращаются теми же
  переменными окружения.
- Актуальные версии: `mcp-watchdog 0.6.0`, `llm-mcp 0.3.0`. `latest.txt`,
  `registry/_registry.json` и диапазоны `project.json` синхронизированы.
- `README.md`: раздел «Сдерживание локальных моделей» (два эшелона, пороги,
  три правила безопасности) и таблица переменных окружения.

### Совместимость

- Узлы-сервисы демон по-прежнему не выгружает: политика `owner-decides` и
  защита ядра не изменились. Троттлинг трогает только модели в памяти Ollama,
  выгрузка полностью обратима — модель поднимается снова по первому запросу.
- Старые вызовы демона без новых параметров работают как раньше (троттлинг
  активен по умолчанию, `-ThrottleMode report` его превращает в наблюдение).

## 0.7 — 2026-10-02

### Изменено

- Переносимость: устранены машинные пути из всех версий реестра. Прежние
  дефолты вида «каталог лаборатории», «каталог отката», «каталог моделей
  Ollama», «файл состояния узлов» и перечень дисков Docker WSL заменены на
  переменные окружения с переносимым резервом:
  - `INVR_LAB_DIR`, `INVR_ROLLBACK_ROOT`, `INVR_OLLAMA_MODELS_DIR`,
    `INVR_LOG_DIR` — приоритет «параметр → переменная процесса → переменная
    уровня User → переносимый дефолт»;
  - `INVR_NODES_FILE` и `INVR_TOOLS_ROOT` — файл состояния узлов монитора
    (шимы `resolve-tools` выставляют `INVR_TOOLS_ROOT` автоматически);
  - `DOCKER_WSL_DATA_DIRS` — дополнительные `ext4.vhdx` через `;`,
    по умолчанию перечисляется только штатный `%LOCALAPPDATA%`;
  - `INVR_WATCHDOG_STATE_FILE` — снимок состояния демона-стража.
  Узлы лаборатории и каталога откатов в `infra-graph` и `opencode-status`
  теперь честно показывают `grey`/`warn`, если каталог не задан или отсутствует.
- Актуальные версии: `infra-graph 0.9.0`, `mcp-watchdog 0.5.1`,
  `mcp-watchdog-guardian 0.2.3`, `opencode-plugins 0.8.0`,
  `opencode-status 0.5.0`, `resolve-tools 0.7.0`. `latest.txt`,
  `registry/_registry.json` и диапазоны `project.json` синхронизированы.
- `resolve-tools` генерирует шимы с `INVR_TOOLS_ROOT=$PSScriptRoot`, поэтому
  инструменты находят свой реестр без ручной настройки окружения.

### Исправлено

- `.gitignore`: рабочие каталоги `state/`, `logs/`, `requests/` и `*.pid` внутри
  каталогов версий `registry/` больше не попадают в публикуемый репозиторий,
  исключения для `monitor/state/` и `mcp-watchdog-guardian/state/`.

## 0.6 — 2026-09-30

### Добавлено

- Непрерывная проверка: `.github/workflows/ci.yml` — на `push` в `main`,
  на `pull_request` в `main` и по ручному запуску. Три проверки:
  PSScriptAnalyzer (статический анализ), синтаксис всех PowerShell-файлов
  (с Pester-заготовкой на будущее) и поиск секретов.
- `tools/ci/invoke-psscriptanalyzer.ps1` — статический анализ с явным набором
  из 40 разрешённых правил PSScriptAnalyzer, отчёт в `artifacts/psscriptanalyzer/`,
  ненулевой код возврата при находках.
- `tools/ci/invoke-syntax-check.ps1` — проверка разбираемости всех
  `*.ps1`/`*.psm1`/`*.psd1` системным парсером PowerShell, отчёт в
  `artifacts/syntax/`.
- `tools/ci/scan-secrets.ps1` — поиск типовых секретов (ключи API, токены,
  пароли, приватные ключи, строки подключения с учётными данными). Значения
  находок никогда не печатаются: только путь, номер строки и тип. Ненулевой
  код возврата при находках, скрипт вызывается из CI.
- Каталог `artifacts/` с отчётами в `.gitignore`; в GitHub отчёты
  публикуются как артефакты сборки.
- Разделы «Непрерывная проверка (CI)» и «Проверка секретов» в `README.md`
  с командами локального запуска.
- Этот журнал изменений.

### Принятые решения

- Pester-тестов в репозитории нет, и выдумывать их не стали: вместо них
  выполняется проверка синтаксиса всех PowerShell-файлов. Шаг с Pester
  оставлен в workflow и сработает автоматически, как только появится каталог
  `tests` с файлами `*.Tests.ps1`.
- Набор правил PSScriptAnalyzer зафиксирован под текущий код: версии
  инструментов в реестре неизменяемы, поэтому «чинить» существующие версии под
  правила анализатора нельзя. Шумные формально-стилевые правила (Write-Host,
  позиционные параметры, пустой catch, BOM, неутверждённые глаголы)
  отключены осознанно, список с причинами — в docblock скрипта.
- Соглашения реестра не менялись: `project.json` не изменялся, версии
  инструментов по-прежнему semver X.Y.Z, каталоги старых версий не тронуты.

## 0.5

Журнал до этой версии не вёлся. Состояние репозитория до 0.6 фиксировали
только коммиты git — см. историю `git log`.

## Соглашения

- Версия проекта в этом журнале — «основная.младшая»: незначительное
  изменение повышает младшую часть, существенное переводит на следующую
  основную.
- Версии инструментов реестра — semver X.Y.Z, неизменяемые: правка
  инструмента = новый каталог версии, `latest.txt` переключает актуальную.
- Даты — ISO (ГГГГ-ММ-ДД), раздел новой версии всегда сверху.
