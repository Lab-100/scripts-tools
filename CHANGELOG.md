# Журнал изменений

Версии проекта — по схеме «основная.младшая» (без третьего компонента),
даты в формате ISO (ГГГГ-ММ-ДД).

Версии инструментов в `registry/<tool>/<version>/` ведутся по semver (X.Y.Z) —
это другая шкала, они неизменяемы и в этот журнал проекта не входят.

## 0.7 — 2026-10-02

### Изменено

- Переносимость: устранены машинные пути из всех версий реестра. Прежние
  дефолты вида «каталог лаборатории», «каталог отката», «каталог моделей
  Ollama», «файл состояния узлов» и перечень дисков Docker WSL заменены на
  переменные окружения с переносимым резервом:
  - `INVR_LAB_DIR`, `INVR_ROLLBACK_ROOT`, `INVR_OLLAMA_MODELS_DIR`,
    `INVR_LOG_DIR` — приоритет «параметр → переменная процесса → переменная
    уровня User → переносимый дефолт»;
  - `INVR_NODES_FILE` и `INVR_TOOLS_ROOT` — файл состояния узлов монитора
    (шимы `resolve-tools` выставляют `INVR_TOOLS_ROOT` автоматически);
  - `DOCKER_WSL_DATA_DIRS` — дополнительные `ext4.vhdx` через `;`,
    по умолчанию перечисляется только штатный `%LOCALAPPDATA%`;
  - `INVR_WATCHDOG_STATE_FILE` — снимок состояния демона-стража.
  Узлы лаборатории и каталога откатов в `infra-graph` и `opencode-status`
  теперь честно показывают `grey`/`warn`, если каталог не задан или отсутствует.
- Актуальные версии: `infra-graph 0.9.0`, `mcp-watchdog 0.5.1`,
  `mcp-watchdog-guardian 0.2.3`, `opencode-plugins 0.8.0`,
  `opencode-status 0.5.0`, `resolve-tools 0.7.0`. `latest.txt`,
  `registry/_registry.json` и диапазоны `project.json` синхронизированы.
- `resolve-tools` генерирует шимы с `INVR_TOOLS_ROOT=$PSScriptRoot`, поэтому
  инструменты находят свой реестр без ручной настройки окружения.

### Исправлено

- `.gitignore`: рабочие каталоги `state/`, `logs/`, `requests/` и `*.pid` внутри
  каталогов версий `registry/` больше не попадают в публикуемый репозиторий,
  исключения для `monitor/state/` и `mcp-watchdog-guardian/state/`.

## 0.6 — 2026-09-30

### Добавлено

- Непрерывная проверка: `.github/workflows/ci.yml` — на `push` в `main`,
  на `pull_request` в `main` и по ручному запуску. Три проверки:
  PSScriptAnalyzer (статический анализ), синтаксис всех PowerShell-файлов
  (с Pester-заготовкой на будущее) и поиск секретов.
- `tools/ci/invoke-psscriptanalyzer.ps1` — статический анализ с явным набором
  из 40 разрешённых правил PSScriptAnalyzer, отчёт в `artifacts/psscriptanalyzer/`,
  ненулевой код возврата при находках.
- `tools/ci/invoke-syntax-check.ps1` — проверка разбираемости всех
  `*.ps1`/`*.psm1`/`*.psd1` системным парсером PowerShell, отчёт в
  `artifacts/syntax/`.
- `tools/ci/scan-secrets.ps1` — поиск типовых секретов (ключи API, токены,
  пароли, приватные ключи, строки подключения с учётными данными). Значения
  находок никогда не печатаются: только путь, номер строки и тип. Ненулевой
  код возврата при находках, скрипт вызывается из CI.
- Каталог `artifacts/` с отчётами в `.gitignore`; в GitHub отчёты
  публикуются как артефакты сборки.
- Разделы «Непрерывная проверка (CI)» и «Проверка секретов» в `README.md`
  с командами локального запуска.
- Этот журнал изменений.

### Принятые решения

- Pester-тестов в репозитории нет, и выдумывать их не стали: вместо них
  выполняется проверка синтаксиса всех PowerShell-файлов. Шаг с Pester
  оставлен в workflow и сработает автоматически, как только появится каталог
  `tests` с файлами `*.Tests.ps1`.
- Набор правил PSScriptAnalyzer зафиксирован под текущий код: версии
  инструментов в реестре неизменяемы, поэтому «чинить» существующие версии под
  правила анализатора нельзя. Шумные формально-стилевые правила (Write-Host,
  позиционные параметры, пустой catch, BOM, неутверждённые глаголы)
  отключены осознанно, список с причинами — в docblock скрипта.
- Соглашения реестра не менялись: `project.json` не изменялся, версии
  инструментов по-прежнему semver X.Y.Z, каталоги старых версий не тронуты.

## 0.5

Журнал до этой версии не вёлся. Состояние репозитория до 0.6 фиксировали
только коммиты git — см. историю `git log`.

## Соглашения

- Версия проекта в этом журнале — «основная.младшая»: незначительное
  изменение повышает младшую часть, существенное переводит на следующую
  основную.
- Версии инструментов реестра — semver X.Y.Z, неизменяемые: правка
  инструмента = новый каталог версии, `latest.txt` переключает актуальную.
- Даты — ISO (ГГГГ-ММ-ДД), раздел новой версии всегда сверху.
